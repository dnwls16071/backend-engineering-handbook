# HTTP Fundamentals and Message Structure

HTTP는 문서, 이미지, JSON 같은 자원의 표현을 주고받는 애플리케이션 프로토콜이다. 클라이언트가 요청을 보내고 서버가 응답한다. 메서드, 상태 코드, 필드의 의미는 여러 HTTP 버전에서 공유한다.

## 1. 무상태성과 연결 재사용

HTTP 요청은 그 자체의 메서드, 대상, 헤더, 콘텐츠로 해석할 수 있다. 필요한 인증 정보를 매 요청에서 전달하고 여러 서버가 같은 검증 규칙과 데이터를 사용하면 한 인스턴스에 요청을 고정할 이유가 줄어든다. 로그인 세션, 장바구니, 결제 진행 상태 같은 애플리케이션 정보는 쿠키나 서버 측 상태 저장소를 통해 이어갈 수 있다.

요청 의미가 무상태라는 성질과 전송 연결의 수명은 별개다. HTTP/1.1은 기본적으로 지속 연결을 사용해 후속 요청에서도 TCP 연결을 재사용할 수 있다. 연결이 불필요하게 반복되면 TCP 설정과 HTTPS의 TLS 협상에 드는 시간이 늘어난다.

## 2. HTTP 버전별 전송

| 버전 | 메시지와 전송 방식 |
| --- | --- |
| HTTP/1.0 | 텍스트 기반 메시지 형식이 널리 쓰이기 시작했다. |
| HTTP/1.1 | 시작 줄과 헤더를 텍스트로 표현하며, 지속 연결과 청크 전송 코딩을 지원한다. |
| HTTP/2 | 한 TCP 연결에서 여러 스트림의 이진 프레임을 교차 전송한다. |
| HTTP/3 | HTTP 의미를 QUIC 스트림에 매핑한다. QUIC은 UDP 위에서 동작하며 스트림별로 순서를 관리한다. |

HTTP/2와 HTTP/3에서는 메서드와 상태 코드 등을 `:method`, `:status` 같은 의사 헤더 필드로 전달한다.

## 3. HTTP/1.1 메시지 읽기

HTTP/1.1 메시지는 시작 줄, 헤더 필드, 빈 줄, 선택적 메시지 본문으로 구성된다. 요청 줄은 메서드·요청 대상·HTTP 버전으로, 응답 상태 줄은 HTTP 버전·상태 코드·선택적인 설명 문구로 읽는다. 응답 처리는 상태 코드의 숫자를 기준으로 한다.

요청 예시

```http
GET /health HTTP/1.1
Host: api.example.com
Accept: application/json

```

응답 예시

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 15

{"status":"ok"}
```

`Host`는 요청할 호스트, `Accept`는 클라이언트가 선호하는 미디어 타입, `Content-Type`은 응답으로 받은 표현의 미디어 타입을 알려 준다. 위 응답에서 `Content-Length`는 마지막 줄의 JSON 15바이트를 나타내며, 실전의 본문 구분 규칙은 메서드·상태 코드·프로토콜 버전에 따라 달라진다.
