# Internet Networking Fundamentals

브라우저가 서버와 통신하려면 이름을 주소로 해석하고, 주소와 포트로 상대를 찾은 뒤, 애플리케이션이 선택한 전송 방식으로 데이터를 보낸다. DNS, IP, TCP·UDP는 각각 이 흐름의 다른 부분을 담당한다.

## 1. IP와 패킷 전달

IP 패킷에는 출발지와 목적지 IP 주소가 담긴다. 라우터는 목적지 주소와 라우팅 정보를 사용해 다음 홉으로 패킷을 전달한다. 여러 패킷이 각기 다른 경로를 이용할 수 있고, 중간에 손실되거나 순서가 뒤바뀔 수 있다. 이러한 상황에서 재전송이나 순서 복구가 필요한지는 상위 프로토콜이 결정한다.

| 계층 | 예 | 담당하는 일 |
| --- | --- | --- |
| 애플리케이션 | HTTP, DNS | 요청, 응답, 이름 해석 같은 메시지 규칙을 정의한다. |
| 전송 | TCP, UDP | 포트로 통신 상대를 구분하고 애플리케이션 데이터를 전달한다. |
| 인터넷 | IP | 서로 다른 네트워크에 있는 IP 주소 사이로 패킷을 전달한다. |
| 링크 | Ethernet, Wi-Fi | 같은 링크에서 다음 장치로 프레임을 보낸다. |

데이터를 보낼 때 각 계층은 자신의 제어 정보를 추가한다. TCP를 사용하는 HTTP 요청이라면 TCP 헤더가 붙은 세그먼트가 IP 패킷에 담기고, 링크 계층은 이를 다음 홉에 전달한다.

## 2. TCP와 UDP

| 항목 | TCP | UDP |
| --- | --- | --- |
| 연결 | 양 끝이 연결 상태를 관리한다. | 전송 전에 연결을 설정하는 교환이 없다. |
| 전달 단위 | 연속된 바이트 스트림 | 메시지 경계를 유지하는 데이터그램 |
| 손실과 순서 | 확인 응답과 재전송을 사용해 수신 측에 순서대로 바이트를 전달한다. | 자체 재전송이나 순서 복구를 제공하지 않는다. |
| 사용 예 | HTTP/1.1과 HTTP/2의 일반적인 전송 | 실시간 미디어 또는 QUIC의 하위 전송 |

TCP의 연결 설정은 일반적으로 `SYN → SYN-ACK → ACK` 순서다. 이 과정에서 양 끝은 초기 시퀀스 번호를 교환한다. 연결 후 애플리케이션은 바이트 스트림을 읽으므로, 상대가 한 번에 쓴 데이터가 수신 측의 한 번의 읽기에 그대로 대응한다고 가정하면 안 된다. UDP 위에 신뢰성이나 혼잡 제어가 필요한 프로토콜은 해당 기능을 별도로 구현할 수 있다.

## 3. 포트와 DNS

포트는 같은 IP 주소에서 어떤 전송 계층 끝점으로 데이터를 보낼지 구분한다. 클라이언트가 `192.0.2.10:51500`에서 `198.51.100.20:443`으로 TCP 연결을 만들면, 서버는 출발지·목적지 IP와 포트 조합으로 이 연결을 구별한다. 여러 연결이 서버의 동일한 `443`번 포트를 공유할 수 있고, TCP와 UDP의 포트 공간은 각각 관리된다.

DNS는 계층적으로 구성된 이름 공간에서 레코드를 조회한다. `example.com`에 대한 `A` 레코드는 IPv4 주소, `AAAA`는 IPv6 주소를 나타낸다. 이름에는 여러 주소가 연결될 수 있고 캐시가 유효하면 기존 조회 결과를 재사용할 수 있다. 이름을 조회한 뒤 브라우저가 실제 요청을 구성하는 과정은 [02번 문서](02_uris_urls_and_browser_request_flow.md)에서 이어진다.
