# HTTP Status Codes and Redirects

상태 코드는 요청 처리 결과를 숫자로 나타낸다. 첫 자리로 응답 계열을 분류하며, 클라이언트가 모르는 상태 코드는 해당 계열의 `x00`과 같은 의미로 처리한다. 인식하지 못하는 상태 코드의 응답은 캐시할 수 없다.

## 1. 상태 코드 계열

| 계열 | 의미 | 예 |
| --- | --- | --- |
| `1xx` | 최종 응답 전의 정보 | `100 Continue` |
| `2xx` | 요청이 성공적으로 처리됨 | `200 OK`, `201 Created` |
| `3xx` | 다른 위치로 이동하거나 캐시된 표현을 재사용하는 등의 후속 처리 | `303 See Other`, `304 Not Modified` |
| `4xx` | 현재 요청을 처리할 수 없는 클라이언트 측 조건 | `400 Bad Request`, `404 Not Found` |
| `5xx` | 서버가 요청을 수행할 수 없는 상태 | `500 Internal Server Error`, `503 Service Unavailable` |

## 2. 결과에 맞는 2xx 선택

| 코드 | 의미 | 사용 예 |
| --- | --- | --- |
| `200 OK` | 요청을 성공적으로 처리했다. | 조회한 작업의 JSON을 반환한다. |
| `201 Created` | 하나 이상의 새 자원이 생성됐다. | `Location: /tasks/42`로 주 자원의 URI를 알린다. |
| `202 Accepted` | 요청을 접수했으며 처리는 아직 완료되지 않았다. | 보고서 생성 작업을 큐에 넣고 진행 상태를 조회할 URI를 제공한다. |
| `204 No Content` | 요청을 성공적으로 처리했고 응답 콘텐츠가 없다. | 삭제 완료만 알린다. |

`202`를 받은 클라이언트는 이를 최종 처리 성공으로 간주할 수 없다. 작업 리소스나 상태 조회 방법을 응답에 포함하면 클라이언트가 완료 여부를 확인할 수 있다.

## 3. 리다이렉트와 메서드

| 코드 | 의미 | 기존 요청이 `POST`인 경우 |
| --- | --- | --- |
| `301 Moved Permanently` | 영구 이동 | 클라이언트가 후속 요청을 `GET`으로 바꿀 수 있다. |
| `302 Found` | 임시 이동 | 클라이언트가 후속 요청을 `GET`으로 바꿀 수 있다. |
| `303 See Other` | 다른 URI에서 결과를 조회하도록 안내 | 일반적으로 `GET`으로 결과를 조회한다. |
| `307 Temporary Redirect` | 임시 이동 | 자동 이동 시 메서드를 유지한다. |
| `308 Permanent Redirect` | 영구 이동 | 자동 이동 시 메서드를 유지한다. |

`300 Multiple Choices`는 여러 선택지를 제공할 수 있다. `304 Not Modified`는 조건부 `GET`·`HEAD`의 결과로 기존 캐시 표현을 재사용할 수 있음을 알린다. 재검증 흐름은 [08번 캐시 문서](08_http_caching_and_conditional_requests.md)에서 다룬다.

**Post/Redirect/Get** 흐름에서는 폼의 `POST /orders`를 처리한 뒤 `303`과 `Location: /orders/42`를 돌려준다. 브라우저는 `GET /orders/42`를 보내 결과를 표시한다. 결과 화면에서 새로 고침하면 이 `GET`이 반복된다. 네트워크 재시도나 중복 제출에 따른 중복 생성은 서버가 별도로 제어한다.

## 4. 4xx와 5xx 구분

| 코드 | 확인할 것 |
| --- | --- |
| `400 Bad Request` | 요청 구문, 프레이밍, 입력 데이터가 서버가 처리할 수 있는 형식인지 본다. |
| `401 Unauthorized` | 해당 자원에 유효한 인증 자격 증명이 필요하다. 서버는 `WWW-Authenticate`로 인증 과제를 제공한다. |
| `403 Forbidden` | 서버가 요청을 이해했으나 허용하지 않는다. 자원 접근 권한과 정책을 확인한다. |
| `404 Not Found` | 자원의 현재 표현을 찾지 못했거나 서버가 자원 존재 여부를 공개하지 않는다. |
| `405 Method Not Allowed` | 대상은 해당 메서드를 허용하지 않는다. 응답의 `Allow`에서 허용 메서드를 확인한다. |
| `500 Internal Server Error` | 서버가 예기치 못한 조건으로 처리를 완료하지 못했다. |
| `503 Service Unavailable` | 과부하나 점검 등 일시적인 사유로 요청을 처리할 수 없다. `Retry-After`가 있으면 재시도 시점을 판단할 수 있다. |

오류 코드는 원인에 맞게 선택하고, API 응답에는 클라이언트가 고칠 수 있는 입력이나 재시도 조건을 설명할 수 있다.
