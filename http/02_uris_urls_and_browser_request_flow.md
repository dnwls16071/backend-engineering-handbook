# URIs, URLs, and Browser Request Flow

URI는 자원을 식별한다. URL은 위치나 접근 방법을 나타내는 URI이고, URN은 이름의 역할을 하는 식별자를 가리킨다. 예를 들어 `https://example.com/docs`는 HTTPS로 접근할 주소이고, `urn:isbn:9780132350884`는 ISBN 이름 공간에 속하는 식별자다.

## 1. URL의 구성

`https://example.com:443/docs/http?lang=ko&level=basic#methods`를 구성 요소로 나누면 다음과 같다.

| 요소 | 예 | 쓰임 |
| --- | --- | --- |
| 스킴 | `https` | 자원에 접근하는 방식과 URL 해석 규칙을 정한다. |
| 호스트 | `example.com` | 요청할 호스트를 지정한다. |
| 포트 | `443` | 전송 계층의 접속 포트를 정한다. HTTPS의 기본 포트라 생략할 수 있다. |
| 경로 | `/docs/http` | 호스트 내부에서 요청 대상을 가리킨다. |
| 쿼리 | `lang=ko&level=basic` | 경로와 함께 자원을 식별하는 데 사용할 수 있는 데이터다. |
| 프래그먼트 | `methods` | 브라우저가 받은 표현 안의 부분을 찾는 데 사용한다. HTTP 요청 대상에는 포함되지 않는다. |

일반 URI 구문에서 authority는 호스트 앞에 `userinfo@`를 포함할 수 있다. HTTP(S) URL에는 사용자 정보를 넣지 않는다. 쿼리에서 `key=value&key=value`는 흔한 인코딩 관례이며, 값에 구분 문자나 공백이 있을 때는 해당 구성 요소에 맞는 인코딩을 사용한다.

## 2. 브라우저에서 서버까지

1. 브라우저가 입력을 URL로 파싱하고 스킴, 호스트, 포트, 경로와 쿼리를 파악한다. 캐시가 응답을 재사용할 수 있으면 네트워크 요청이 생략될 수 있다.
2. 네트워크 접근이 필요하면 주소 캐시 또는 DNS를 사용해 호스트의 주소를 찾는다. 재사용할 연결이 없으면 새 연결을 맺는다. HTTPS의 HTTP/1.1·HTTP/2는 일반적으로 TCP와 TLS를, HTTP/3는 QUIC를 사용한다.
3. 브라우저가 메서드, 요청 대상, 헤더를 전송한다. 서버는 요청 대상을 처리하고 상태 코드와 헤더, 필요한 경우 콘텐츠를 응답한다.
4. 브라우저는 응답에 따라 화면을 렌더링하거나 리다이렉트를 따르고, 문서가 참조하는 CSS와 이미지 같은 하위 자원을 추가로 요청할 수 있다.

## 3. HTTP/1.1 요청으로 읽기

서버에 직접 연결했다고 가정하면 요청 라인에는 경로와 쿼리가 들어가고, 호스트 정보는 `Host`에서 확인할 수 있다. 마지막 빈 줄은 헤더 구간의 끝이다.

```http
GET /docs/http?lang=ko&level=basic HTTP/1.1
Host: example.com

```

`#methods`는 브라우저가 받아온 문서에서 처리한다. HTTP 버전별 메시지 형식은 [03번 문서](03_http_fundamentals_and_message_structure.md)에서 다룬다.
