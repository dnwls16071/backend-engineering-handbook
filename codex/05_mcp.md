# MCP: Codex를 외부 도구와 실제 시스템에 연결하기

## 1. 도구 연동을 공통 프로토콜로 표준화한다

- **MCP(Model Context Protocol)는 AI 에이전트가 도구, API, 데이터베이스와 애플리케이션에 일관된 방식으로 연결되도록 하는 표준 프로토콜이다.**
- 각 도구와 에이전트 사이에 개별 연동을 만들면 개발 비용이 늘고 통합 방식이 분산된다.
- MCP는 연결 방식을 표준화해 도구의 재사용과 여러 플랫폼 간 연동을 돕는다.
- 에이전트마다 모든 시스템의 접근 방식을 직접 구현하는 부담을 줄일 수 있다.

## 2. 클라이언트와 서버가 외부 시스템 접근을 연결한다

| 구성요소 | 역할 |
| :--- | :--- |
| 사용자 | 수행할 작업을 요청한다. |
| Codex·AI 에이전트 | 요청을 해석하고 필요한 도구 사용을 결정한다. |
| MCP 클라이언트 | 에이전트와 MCP 서버 사이의 통신을 담당한다. |
| MCP 서버 | 외부 도구와 시스템의 기능을 에이전트가 사용할 수 있도록 제공한다. |
| 외부 도구·API·데이터베이스 | 실제 데이터를 조회하거나 요청한 동작을 수행한다. |

- 사용자의 요청은 에이전트, MCP 클라이언트와 서버를 거쳐 외부 시스템의 조회나 실행으로 이어진다.
- **MCP는 모델의 판단을 실제 시스템의 기능과 연결하는 통로이다.**

## 3. Codex의 작업 범위를 외부 시스템으로 확장한다

- Codex는 MCP 서버를 통해 저장소를 읽고, API를 조회하고, 인프라에 접근할 수 있다.
- 여러 도구를 연결해 개발 작업과 반복적인 워크플로를 자동화할 수 있다.

| 연동 분야 | 활용 대상과 예시 |
| :--- | :--- |
| 소스 관리 | GitHub와 코드 저장소 |
| 클라우드·인프라 | AWS, GCP와 Kubernetes |
| 데이터베이스 | Neo4j 등 데이터 저장·조회 시스템 |
| 보안 | 보안 분석 도구 |
| 문서 | 기술 문서와 개발 지식 |
| 모니터링 | 로그, 상태와 운영 지표 조회 도구 |
| DevOps | 개발·운영 작업 흐름을 지원하는 도구 |

- 같은 에이전트가 코드, 문서와 운영 데이터를 함께 활용할 수 있다.
- 연결한 시스템과 부여한 권한에 따라 수행 가능한 작업의 범위가 달라진다.

## 4. config.toml과 CLI로 MCP를 설정한다

- Codex는 `config.toml`과 CLI 명령을 통한 MCP 설정을 지원한다.
- 서버별 설정은 `[mcp_servers.<name>]` 아래에서 관리한다.
- 이미 연결 정보가 등록된 `context7` 서버의 활성화 설정은 다음과 같다.

```toml
[mcp_servers.context7]
enabled = true
```

- `enabled`는 해당 서버의 활성화 여부를 정한다.
- 서버 연결에 필요한 설정과 활성화 여부를 구분해 관리한다.

## 5. 실행 위치에 맞는 전송 방식을 선택한다

| 방식 | 연결 형태 | 특징 |
| :--- | :--- | :--- |
| STDIO | 로컬 프로세스와 표준 입출력으로 통신한다. | 로컬 도구를 단순하게 연결하는 데 적합하다. |
| Streamable HTTP | HTTP를 통해 원격 MCP 서버에 연결한다. | 클라우드 환경과 여러 사용자가 공유하는 인프라에 적합하다. |

- **로컬 프로세스로 실행할지, 원격의 공용 서버에 접근할지에 따라 연결 방식을 선택한다.**

## 6. Kubernetes 장애 분석에 여러 도구를 연결한다

- 사용자가 “Kubernetes 운영 환경의 문제를 분석해 달라”고 요청하는 상황을 예로 들 수 있다.

1. Kubernetes MCP를 호출한다.
2. Pod의 현재 상태를 읽는다.
3. 로그에서 오류와 경고를 확인한다.
4. 모니터링 도구를 조회해 관련 데이터를 수집한다.
5. 수집한 정보를 바탕으로 문제 해결 방안을 제안한다.

- 에이전트는 한 번의 응답을 생성하는 데서 더 나아가 필요한 정보를 순서대로 수집하고 분석할 수 있다.
- 분석 결과를 제안하는 단계와 실제 인프라를 변경하는 단계는 구분해 권한을 부여한다.

## 7. 도구 연결과 함께 권한과 실행 범위를 통제한다

| 위험 | 설명 |
| :--- | :--- |
| 프롬프트 인젝션 | 도구가 가져온 외부 콘텐츠가 에이전트의 판단과 행동을 바꿀 수 있다. |
| 과도한 권한 | 작업에 필요하지 않은 시스템 변경까지 가능해질 수 있다. |
| 자격 증명 유출 | 외부 시스템 연결에 쓰는 인증 정보가 노출될 수 있다. |
| 안전하지 않은 자동화 | 잘못된 판단이 도구 실행을 통해 실제 피해로 이어질 수 있다. |

- **최소 권한을 적용한다.** 작업에 필요한 데이터와 동작만 허용한다.
- **샌드박스를 사용한다.** 실행 환경과 접근 범위를 제한한다.
- **승인 절차를 둔다.** 중요한 동작은 실행 전에 확인하도록 한다.
- **신뢰할 수 있는 MCP 서버만 연결한다.** 서버 선택도 보안 검토의 대상이다.

## 8. 표준화와 보안을 함께 고려한다

- MCP는 AI 에이전트를 실제 시스템과 연결하고, 도구를 재사용할 수 있는 공통 기반을 제공한다.
- 여러 AI 플랫폼과 도구 생태계에서 같은 연결 방식을 활용할 수 있다는 점에 의미가 있다.
- 연결 가능한 도구가 많아질수록 실행 범위와 권한을 명확히 관리해야 한다.
- **도구 연결을 표준화하는 것과 그 도구를 안전하게 사용하도록 통제하는 일은 함께 설계해야 한다.**
