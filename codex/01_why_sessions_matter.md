# Codex 세션: 실행 이력을 보존하고 작업을 이어가는 방법

## 1. 세션이 필요한 이유

- **Codex 세션은 대화와 실행 이력을 보존해 중단한 작업을 나중에 이어갈 수 있도록 하는 작업 단위이다.**
- 모든 Codex 상호작용은 세션 안에서 이루어진다.
- 이전 기록이 없으면 작업의 배경을 다시 설명해야 하고, 긴 작업이나 디버깅을 이어가기 어렵다.
- 세션을 활용하면 이전 조사와 실행 결과를 다시 확인하고 프로젝트 맥락을 복원할 수 있다.
- 세션의 가치는 한 번의 응답을 저장하는 데서 끝나지 않고, 여러 시간이나 날짜에 걸친 작업의 연속성을 유지하는 데 있다.

## 2. 대화뿐 아니라 작업 과정도 저장한다

| 저장 대상 | 포함되는 내용 |
| :--- | :--- |
| 대화 이력 | 사용자 프롬프트와 어시스턴트 응답 |
| 도구 실행 이력 | 도구 호출, 터미널 명령과 실행 결과 |
| 파일 변경 이력 | 작업 중 이루어진 파일 수정 기록 |
| 계획 이력 | 대화와 실행 기록에 남은 작업 계획 |
| 실행 메타데이터 | 타임스탬프, 토큰 사용량과 실행 로그 |

- 세션은 로컬에 **JSONL 형식의 대화·실행 기록**으로 저장된다.
- 일반적인 저장 위치는 `~/.codex/sessions/`이며, 파일 이름은 `rollout-xxxx.jsonl` 형태이다.
- 이 기록에는 대화 내용뿐 아니라 도구 출력과 실행 메타데이터도 포함될 수 있다.

## 3. 기록을 통해 맥락을 다시 구성한다

- **세션을 재개하면 모델은 저장된 이력을 바탕으로 작업 맥락을 다시 구성한다.**
- 대화, 명령, 출력과 도구 결과가 저장된다.
- 모델의 숨겨진 추론 상태나 일시적인 내부 사고 상태는 저장되지 않는다.
- 따라서 재개할 때 목표와 현재 진행 상황을 다시 짚어 주면 다음 작업의 방향을 맞추는 데 도움이 된다.

## 4. 중단한 세션을 재개한다

| 실행 위치 | 명령어 | 설명 |
| :--- | :--- | :--- |
| Codex 내부 | `/resume` | 이전 세션 선택기를 열고 선택한 세션의 대화 맥락을 복원한다. |
| 터미널 | `codex continue` | 이전 작업을 이어서 진행한다. |
| 터미널 | `codex continue <session-id>` | 지정한 세션을 이어서 진행한다. |

- `/resume`으로 중단한 작업을 재개하거나 다른 세션으로 전환할 수 있다.
- 예를 들어 아침에 `codex`로 작업을 시작하고 몇 시간 뒤 터미널을 닫더라도, 다음 날 세션을 재개해 작업을 이어갈 수 있다.
- 재개한 뒤에는 이전 대화와 실행 결과를 참고해 후속 작업을 진행한다.

## 5. 세션을 효과적으로 활용하는 습관

- **작업 범위를 명확히 한다.** 세션에서 해결하려는 목표를 구체적으로 정한다.
- **중요한 작업은 기존 세션에서 이어간다.** 이전 디버깅이나 조사 기록을 활용해 맥락을 회복한다.
- **지속적으로 필요한 프로젝트 맥락은 `AGENTS.md`에 남긴다.** 프로젝트의 규칙과 배경을 지속적으로 참고할 수 있도록 한다.
- **지나치게 긴 세션은 피한다.** 세션을 무한히 늘리는 대신 작업 범위를 관리한다.
- **재개 직후 방향을 다시 맞춘다.** 모델이 목표와 진행 상황을 다시 파악하도록 안내한다.

## 6. 핵심 정리

- 세션은 장시간에 걸친 Codex 작업을 이어가는 기반이다.
- 보존되는 것은 대화와 실행 이력이며, 재개 시 모델은 그 기록으로 맥락을 재구성한다.
- 이전 기록을 활용하는 것과 함께 작업 범위 관리, `AGENTS.md` 활용, 재개 시 상황 설명이 중요하다.
