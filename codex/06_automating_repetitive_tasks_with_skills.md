# Skills: 반복 작업을 재사용 가능한 워크플로로 만들기

## 1. 반복해서 설명하던 작업 절차를 재사용한다

- **Skill은 AI 에이전트가 반복 작업을 일관되게 수행하도록 만드는 워크플로 작성 형식이다.**
- 지침, 작업 순서, 스크립트, 템플릿, 참고 문서와 도구 사용법을 함께 담을 수 있다.
- 검증된 절차를 재사용하면 같은 내용을 매번 프롬프트로 설명하는 부담을 줄일 수 있다.
- 반복 설명에 의존할 때 생기는 결과의 불일치, 관례 누락과 작업 절차의 이탈을 줄이는 데 도움이 된다.
- 팀 표준을 따르고 도구를 올바르게 사용하도록 안내해 여러 단계의 작업을 안정적으로 수행하게 한다.

## 2. SKILL.md를 중심으로 필요한 파일을 구성한다

```text
my-skill/
├── SKILL.md
├── scripts/
├── templates/
├── examples/
└── docs/
```

| 구성요소 | 역할 |
| :--- | :--- |
| `SKILL.md` | 스킬의 설명과 실행 지침을 담는 핵심 파일 |
| `scripts/` | 작업을 돕는 스크립트 |
| `templates/` | 반복해서 사용할 결과물의 기본 형식 |
| `examples/` | 지침을 구체적으로 이해하기 위한 예시 |
| `docs/` | 작업에 필요한 참고 문서 |

- **핵심은 `SKILL.md`이며, 나머지 파일은 필요에 따라 추가한다.**
- 모든 내용을 지침에 나열하기보다 실행 코드, 템플릿과 참고 내용을 역할에 맞게 나눈다.

## 3. 이름과 설명, 실행 지침을 명확히 작성한다

- `SKILL.md`에는 스킬의 이름과 설명을 메타데이터로 작성하고, 본문에 수행할 작업을 적는다.
- REST API 구현을 검토하는 스킬은 다음처럼 구성할 수 있다.

```markdown
---
name: api-review
description: Review REST API implementations.
---

# Instructions

- 인증 처리를 확인한다.
- 오류 처리를 검증한다.
- 페이지네이션 지원을 확인한다.
- OpenAPI 문서를 검증한다.
```

- `name`은 스킬을 식별하는 이름이다.
- `description`은 스킬이 어떤 작업을 위한 것인지 설명한다.
- 본문에는 에이전트가 수행할 검사와 절차를 구체적으로 작성한다.

## 4. 스킬을 발견하고 호출하는 방식을 이해한다

- Codex는 스킬 디렉터리에서 `SKILL.md`를 찾아 사용할 수 있는 스킬을 발견한다.
- 일반적인 저장 위치는 `~/.codex/skills/`이다.
- 스킬은 개인 공통 용도, 프로젝트 전용 또는 팀 공유 형태로 관리할 수 있다.
- **사용자가 스킬을 명시적으로 호출하거나, Codex가 작업 맥락에 따라 적절한 스킬을 선택할 수 있다.**
- 예를 들어 `$api-review`로 API 검토 스킬을 명시적으로 호출할 수 있다.

## 5. 개발·데이터·문서 작업에 적용한다

| 분야 | 활용 예시 |
| :--- | :--- |
| 엔지니어링 | PR 리뷰, Terraform 검증, Kubernetes 배포 점검과 장애 대응 |
| 데이터 | SQL 리뷰, ETL 검증과 데이터 품질 검사 |
| 콘텐츠 | 문서 생성, 릴리스 노트 작성과 스타일 규칙 적용 |

- 반복되는 절차를 스킬로 만들면 담당자나 세션이 바뀌어도 같은 기준으로 작업할 수 있다.
- 팀 지식을 공유하고 신규 구성원이 작업 방식을 익히는 데도 활용할 수 있다.

## 6. Skills와 플러그인의 역할을 구분한다

| 구분 | 역할 |
| :--- | :--- |
| Skills | 재사용할 지침과 워크플로를 정의한다. |
| 플러그인 | Skills와 외부 연동 등을 묶어 설치·배포하는 단위이다. |

- **작업 절차 자체는 Skill로 설계하고, 배포와 연동이 필요하면 플러그인으로 묶는다.**
- 스킬의 책임은 작업 방법을 정의하는 데 있고, 플러그인의 책임은 관련 기능을 설치 가능한 형태로 제공하는 데 있다.

## 7. 작고 명확하며 조합 가능한 단위로 유지한다

- **하나의 목적에 집중한다.** 서로 다른 작업을 거대한 스킬 하나에 모두 넣지 않는다.
- **모듈로 나누고 조합할 수 있게 한다.** 필요한 절차를 재사용할 수 있도록 책임을 분명히 한다.
- **모호한 지시를 피한다.** 무엇을 어떤 순서로 확인해야 하는지 명확히 적는다.
- **숨은 가정을 줄인다.** 작업에 필요한 조건을 에이전트가 추측하지 않도록 한다.
- **예시를 포함한다.** 기대하는 작업 방식과 결과를 구체적으로 전달한다.
- **실패 처리도 설명한다.** 정상 흐름뿐 아니라 문제가 생겼을 때 어떻게 대응할지 정한다.

## 8. 조직의 운영 지식을 실행 가능한 절차로 남긴다

- 스킬에는 엔지니어링 표준, 배포 규칙, 보안 정책과 아키텍처 결정을 반영할 수 있다.
- 개인의 경험에만 의존하던 지식을 팀이 공유하는 워크플로로 바꿀 수 있다.
- 온보딩을 확장하고 반복 작업의 신뢰성을 높이는 데 도움이 된다.
- **Skills는 조직이 축적한 작업 방식을 에이전트가 재사용할 수 있도록 만드는 운영 지식의 기반이다.**
