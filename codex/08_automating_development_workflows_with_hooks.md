# Hooks: 이벤트에 맞춰 개발 워크플로를 자동화하기

## 1. 에이전트 작업 중 필요한 동작을 자동으로 실행한다

- **Hooks는 Codex의 작업 흐름에서 특정 이벤트가 발생할 때 사용자 정의 스크립트를 실행하는 확장 기능이다.**
- 반복적인 검증, 팀 정책 점검과 외부 시스템 연동을 작업 흐름에 연결할 수 있다.
- 사용자가 매번 테스트나 알림을 요청하지 않아도 정해진 시점에 같은 절차를 수행하게 한다.
- 작업의 일관성, 자동화 수준과 운영 가시성을 높이는 데 활용한다.

## 2. 이벤트 발생 시점에 맞춰 작업을 연결한다

- 기본 흐름은 이벤트 발생, 훅 실행, 결과 반환이다.
- **어떤 작업을 실행할지와 함께 언제 실행할지를 정하는 것이 핵심이다.**

| 이벤트 | 실행 시점 | 활용 예시 |
| :--- | :--- | :--- |
| `SessionStart` | 새 Codex 세션이 시작될 때 | 저장소 상태 확인, 환경 검증, 프로젝트 지침 로드와 세션 메타데이터 초기화 |
| `UserPromptSubmit` | 사용자가 프롬프트를 제출한 직후 | 프롬프트 로깅, 감사 추적, 정책 검사와 입력 필터링 |
| `PermissionRequest` | 제한된 동작에 대한 권한을 요청할 때 | 보안 모니터링, 승인 요청 기록과 위험 명령 탐지 |
| `PostToolUse` | 도구 실행이 끝난 뒤 | 자동 포맷팅, 린트와 보안 검사 |
| `PreCompact` | 컨텍스트 압축 직전 | 프로젝트 상태, 메모리 파일과 작업 요약 저장 |
| `PostCompact` | 컨텍스트 압축 직후 | 프로젝트 상태 재로드, 요약 검증과 작업 맥락 복원 |
| `SubagentStart` | 하위 에이전트가 생성될 때 | 에이전트 수명주기 추적과 병렬 작업 모니터링 |
| `SubagentStop` | 하위 에이전트의 실행이 끝날 때 | 성능 측정, 정리 작업과 완료 추적 |
| `Stop` | Codex가 응답을 마치고 현재 상호작용을 끝낼 때 | 세션 요약, 변경 기록, 릴리스 노트와 최종 지표 저장 |

## 3. 세션과 도구 실행 흐름에 필요한 훅을 배치한다

1. 세션이 시작되면 `SessionStart`로 작업 환경을 확인한다.
2. 사용자가 요청을 제출하면 `UserPromptSubmit`으로 입력을 기록하거나 검사한다.
3. 제한된 동작의 승인이 필요하면 `PermissionRequest`로 관련 정보를 점검한다.
4. 도구 실행이 끝나면 `PostToolUse`로 결과에 필요한 후속 작업을 수행한다.
5. 응답이 끝나면 `Stop`으로 요약과 실행 지표를 저장한다.

- 하위 에이전트를 사용하는 작업에는 `SubagentStart`와 `SubagentStop`을 연결할 수 있다.
- 컨텍스트 압축이 발생할 때는 `PreCompact`와 `PostCompact`로 상태 보존과 복원을 처리한다.
- 모든 이벤트가 매번 발생하는 것은 아니므로 실제 작업에서 필요한 시점을 선택한다.

## 4. 컨텍스트 압축 전후에 작업 상태를 관리한다

- 컨텍스트가 커져 압축이 필요해지면 `PreCompact`에서 중요한 프로젝트 상태와 작업 요약을 저장할 수 있다.
- 메모리 파일을 유지하거나 작업 문서를 갱신하는 데도 활용한다.
- 압축이 끝난 뒤에는 `PostCompact`로 저장한 상태를 다시 읽고 요약을 검증할 수 있다.
- **압축 전 저장과 압축 후 복원을 연결해 작업 맥락의 연속성을 관리한다.**

## 5. 도구 실행 후 검증과 품질 검사를 자동화한다

- `PostToolUse`는 Bash, Edit, Write, Read, Grep 같은 도구의 실행 후 후속 작업을 연결하는 데 활용할 수 있다.

| 작업 | 명령 예시 |
| :--- | :--- |
| 자동 포맷팅 | `black .` |
| 린트 | `ruff check .` |
| 보안 검사 | `gitleaks detect` |
| 테스트 | `pytest` |

- 자동 테스트의 예시는 코드 수정, 훅 실행, `pytest` 실행, 결과 기록으로 이어지는 흐름이다.
- 반복적인 검증을 작업 흐름에 포함하면 오류를 일찍 발견하고 수동 확인을 줄일 수 있다.
- 팀의 공통 절차로 테스트, 린트, 보안 검사와 로그 생성을 연결할 수 있다.

## 6. 작업 완료 알림과 외부 시스템을 연동한다

- 작업이 끝나면 훅이 Slack API를 호출해 팀에 완료 알림을 보내는 흐름을 구성할 수 있다.
- 이메일이나 데스크톱 알림도 같은 방식으로 연결할 수 있다.
- 팀이 작업 상태를 파악하고 후속 협업을 시작하는 데 도움이 된다.
- 입력, 승인 요청, 도구 실행과 완료 시점의 로그를 남겨 감사와 모니터링에도 활용한다.

## 7. Rules·AGENTS.md·Skills와 역할을 나눈다

| 구성요소 | 역할 |
| :--- | :--- |
| Rules | 명령 실행의 허용 범위와 승인·차단 정책을 정한다. |
| `AGENTS.md` | 프로젝트 맥락과 지속적으로 적용할 지침을 전달한다. |
| Skills | 반복해서 사용할 작업 지식과 절차를 정의한다. |
| Hooks | 이벤트에 맞춰 스크립트를 실행하고 작업 흐름을 자동화한다. |

- Rules로 실행 범위를 통제하고 Hooks로 검증과 후속 작업을 자동화할 수 있다.
- `AGENTS.md`에 공통 지침을 두고, Skills에 재사용할 절차를 정의하고, Hooks로 필요한 시점의 실행을 연결한다.
- **작업 지침, 재사용할 절차, 실행 정책과 자동 실행 시점을 각각의 역할에 맞게 관리한다.**

## 8. 훅도 실제 명령을 실행하는 코드로 관리한다

- 훅은 셸 스크립트를 실행하고, 외부 API를 호출하고, 파일을 수정할 수 있다.
- 자격 증명과 비밀 정보를 사용하는 훅은 정보 노출과 권한 범위를 함께 검토해야 한다.
- **최소 권한을 적용한다.** 훅이 필요한 작업만 수행하도록 접근 범위를 제한한다.
- **감사 로그를 남긴다.** 자동으로 어떤 동작이 실행됐는지 확인할 수 있게 한다.
- **버전 관리에 포함한다.** 훅의 동작과 변경 이력을 추적한다.
- **검토한 뒤 신뢰한다.** 실행할 스크립트와 외부 연동 내용을 확인한다.
- 이벤트 기반 자동화로 일관성을 높이는 동시에 실제 명령 실행에 따르는 책임도 관리한다.
