# 프롬프트 인젝션: 외부 콘텐츠가 에이전트의 행동을 바꾸는 위험

## 1. 입력과 맥락을 통해 에이전트의 행동을 조작한다

- **프롬프트 인젝션은 모델이 기존 규칙을 무시하거나 의도하지 않은 행동을 하도록 지시를 끼워 넣는 공격이다.**
- 공격자는 사용자 입력이나 외부 콘텐츠를 통해 모델의 판단과 작업 방향을 바꾸려 한다.
- 애플리케이션, 서버와 데이터베이스뿐 아니라 모델이 읽는 프롬프트와 맥락도 공격 대상이 된다.
- 에이전트가 이메일, 일정, 데이터베이스와 인프라에 접근하고 코드를 실행할수록 잘못된 판단이 실제 시스템에 미치는 영향도 커진다.

## 2. 직접 공격과 간접 공격을 구분한다

| 구분 | 공격 경로 | 예시 |
| :--- | :--- | :--- |
| 직접 프롬프트 인젝션 | 공격자가 모델에 악의적인 지시를 직접 입력한다. | 기존 규칙을 무시하고 파일 삭제, 전체 주문 환불이나 무단 송금을 수행하도록 요구한다. |
| 간접 프롬프트 인젝션 | 에이전트가 읽는 외부 데이터에 지시를 숨긴다. | 웹페이지의 HTML 주석에 사용자 데이터를 외부로 전송하라는 문구를 넣는다. |

- 직접 공격은 사용자 입력으로 기존 규칙과 충돌하는 행동을 유도한다.
- 간접 공격은 정상적인 작업 중 읽게 되는 콘텐츠를 공격 경로로 사용한다.
- 웹사이트, PDF, 문서, 이메일, Slack 메시지와 GitHub 저장소 등 다양한 입력에 악의적인 지시가 포함될 수 있다.
- **사용자가 직접 요청하지 않은 행동도 외부 콘텐츠를 통해 유도될 수 있다는 점이 간접 공격의 핵심이다.**

## 3. 외부 데이터를 지시로 받아들이면 신뢰 경계가 무너진다

1. 사용자가 웹페이지나 문서의 조회·요약을 요청한다.
2. 에이전트가 외부 콘텐츠를 읽는다.
3. 콘텐츠 안에서 기존 규칙을 무시하거나 다른 행동을 수행하라는 문구를 발견한다.
4. 그 문구를 분석할 데이터가 아니라 따라야 할 지시로 해석한다.
5. 원래 작업과 무관한 응답이나 도구 실행으로 이어진다.

- **외부 콘텐츠는 처리할 데이터이며, 에이전트의 권한이나 작업 목적을 바꾸는 지시가 아니다.**
- 내용이 명령문처럼 보이더라도 시스템 지침이나 사용자의 요청과 같은 권한을 부여해서는 안 된다.
- 웹페이지의 숨겨진 문구나 문서 속 지시도 같은 기준으로 다룬다.

## 4. 이메일 에이전트에서는 정보 유출로 이어질 수 있다

- 이메일 에이전트는 메일 읽기, 요약과 답장 전송 기능을 함께 가질 수 있다.
- 공격자는 메일 본문에 에이전트의 행동을 바꾸는 지시를 삽입할 수 있다.
- 메일을 읽고 내용을 해석하는 과정에서 본문을 실행 지시로 받아들이면 데이터 유출로 이어질 수 있다.
- 피해에는 개인정보 침해, 기밀 정보 노출과 자격 증명 유출이 포함된다.
- 읽기와 전송 기능이 함께 있을 때는 읽은 콘텐츠가 후속 행동을 결정하지 못하도록 통제해야 한다.

## 5. 도구 호출은 잘못된 판단을 실제 행동으로 연결한다

| 시스템 | 공격이 미칠 수 있는 영향 |
| :--- | :--- |
| 응답만 생성하는 챗봇 | 잘못된 답변이나 민감한 정보가 포함된 응답 |
| 도구를 사용하는 에이전트 | 잘못된 응답에 더해 명령 실행, API 호출과 시스템 변경 |

- 프롬프트 인젝션에 영향을 받은 에이전트가 AWS API를 호출하면 리소스 삭제 같은 실제 피해로 이어질 수 있다.
- 명령 실행, 외부 API 접근과 시스템 수정 권한이 많을수록 공격의 영향 범위가 커진다.
- **모델의 응답뿐 아니라 그 응답에서 파생되는 도구 호출과 실행 결과까지 검토해야 한다.**

## 6. 지시 구분과 실행 통제를 여러 겹으로 적용한다

| 방어 방법 | 적용 방식 |
| :--- | :--- |
| 지시 계층 구분 | 시스템 지침, 사용자 요청과 외부 콘텐츠를 구분한다. |
| 최소 권한 | 조회만 필요한 작업에는 읽기 전용 접근을 부여한다. |
| 사용자 승인 | 데이터베이스 삭제 같은 중요한 작업은 실행 전에 승인을 받는다. |
| 도구 제한 | 허용된 API와 동작만 사용할 수 있도록 제한한다. |
| 실행 전 검증 | 모델이 생성한 행동과 도구 호출이 허용된 범위인지 확인한다. |
| 샌드박스 | 실행 환경과 접근 가능한 리소스를 제한한다. |
| 맥락 격리 | 외부 콘텐츠가 지시와 섞여 작업 방향을 바꾸지 않도록 구분한다. |
| 감사 로그 | 에이전트의 판단에 따른 도구 호출과 실행 이력을 기록한다. |

- 외부 콘텐츠를 신뢰하지 않는다는 원칙을 권한과 실행 정책에도 반영한다.
- 중요한 작업의 허용 여부를 모델의 판단에만 맡기지 않고 승인과 권한 제어로 통제한다.
- 각 방어 수단을 함께 적용해 공격 경로와 피해 범위를 줄인다.

## 7. 자동화의 범위와 함께 보안 책임도 설계한다

- 프롬프트 인젝션은 LLM 기반 시스템에서 맥락과 지시를 다루는 과정의 근본적인 보안 과제이다.
- 사용자 입력뿐 아니라 에이전트가 읽는 문서와 외부 데이터에도 악의적인 지시가 있을 수 있다고 가정한다.
- 자동화로 생산성이 높아질수록 에이전트가 접근할 정보와 수행할 행동을 명확히 제한해야 한다.
- **외부 콘텐츠를 데이터로 취급하고, 실제 실행은 최소 권한·승인·검증으로 통제한다.**
