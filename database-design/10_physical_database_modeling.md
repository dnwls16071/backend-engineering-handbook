# Physical Database Modeling

물리적 모델링은 논리 모델에 정의한 데이터와 규칙을 선택한 DBMS에서 구현하는 단계다. 테이블과 열의 이름, 자료형, 제약 조건, 인덱스, 저장 설정을 결정한다. 결과물로 테이블 정의서와 실행 가능한 DDL을 남기고, 실제 쿼리와 데이터로 가정을 검증한다. [Oracle Data Modeler의 물리 모델](https://docs.oracle.com/en/database/oracle/sql-developer-data-modeler/22.2/dmdug/data-modeler-concepts-usage.html)

## 1. 논리 모델을 물리 모델로 옮기기

| 논리적 결정 | 물리 모델에 기록할 사항 |
| --- | --- |
| 엔티티와 속성 | 테이블명, 열 이름, 자료형과 길이 |
| 식별과 필수 여부 | 기본 키, 대체 후보 키의 `UNIQUE`, `NOT NULL` |
| 관계와 삭제 정책 | 외래 키 열, 참조 대상, 삭제·변경 동작 |
| 조회와 쓰기 패턴 | 자주 사용하는 필터, 조인, 정렬에 대응하는 인덱스 |
| 운영 조건 | 예상 데이터량, 보관 기간, 변경·복구 방식 |

이름은 용어 사전에 맞추고 예약어와 모호한 약어는 피한다. 이 시리즈의 예제는 소문자 `snake_case`를 쓰며, 주문 테이블에 `orders`, 주문 기본 키와 참조 열에 `order_id`를 쓴다. 단수형과 복수형 중 하나를 팀 관례에 맞춰 일관되게 적용한다. 물리 이름과 DBMS의 식별자 표기 규칙은 함께 검토한다. [MySQL 스키마 객체 이름](https://dev.mysql.com/doc/refman/8.4/en/identifiers.html)

## 2. 저장할 값의 의미로 자료형 고르기

| 데이터 | 선택 기준 | MySQL 8.4 예시 |
| --- | --- | --- |
| 문자 | 길이가 일정한 코드와 길이가 달라지는 이름을 구분한다. 길이, 문자 집합, 대소문자·정렬 규칙을 확인한다. | 두 글자 국가 코드 `CHAR(2)`, 상품명 `VARCHAR(120)` |
| 수량과 식별자 | 업무에서 가능한 값의 범위와 테이블 수명 동안 필요한 식별자 수를 확인한다. 외래 키는 참조 키와 호환되는 형식으로 맞춘다. | 수량 `INT`, 장기간 증가하는 식별자 `BIGINT` |
| 금액과 비율 | 반올림 정책과 필요한 소수 자릿수를 정한다. 금액은 정확한 십진 자료형이나 통화 최소 단위 정수를 사용한다. | 금액 `DECIMAL(12,2)`, 통화 코드 `CHAR(3)` |
| 날짜와 시각 | 날짜만 필요한지, 특정 지역의 벽시계 시각인지, 한 사건의 절대 시점인지 구분한다. | 달력 날짜 `DATE`, UTC로 저장한다는 규약을 정한 `DATETIME(6)` |

MySQL의 `TIMESTAMP`는 세션 시간대를 기준으로 UTC 저장과 조회 시 역변환을 적용한다. `DATETIME`은 같은 변환을 자동으로 적용하지 않는다. 시각 범위와 시간대 처리 방식은 DBMS마다 다르므로, 사건의 시점을 저장할 때는 입력과 조회의 시간대 기준을 명시한다. [MySQL 자료형](https://dev.mysql.com/doc/refman/8.4/en/data-types.html) · [정확한 고정소수점](https://dev.mysql.com/doc/refman/8.4/en/fixed-point-types.html) · [날짜와 시간 자료형](https://dev.mysql.com/doc/refman/8.4/en/datetime.html)

## 3. 인덱스와 역정규화 결정하기

인덱스를 고르기 전에 실제 쿼리의 필터, 반환 범위, 정렬 순서를 확인한다. 예를 들어 회원별 주문을 최신순으로 읽는 조회는 `(member_id, ordered_at, order_id)`를 후보로 잡을 수 있다. 동일 시각의 주문은 `order_id`로 순서를 확정한다. 실행 계획과 데이터 분포를 확인하고, 쓰기 비용과 저장 공간도 비교한다. [복합 인덱스](../database/08_composite_and_covering_indexes.md) · [MySQL EXPLAIN](https://dev.mysql.com/doc/refman/8.4/en/explain.html)

역정규화는 조회 경로나 집계 비용을 줄이기 위해 계산값이나 중복 데이터를 의도적으로 저장하는 선택이다. 주문 항목에서 계산한 총액을 주문에도 저장한다면 어느 값이 원본인지, 언제 다시 계산하는지, 불일치를 어떻게 발견하는지 정의해야 한다. 상품의 현재 가격과 주문 시점에 기록한 단가는 각각 다른 시점의 사실이다. 주문 단가는 주문 당시 거래를 재현하는 데 사용한다.

## 4. 테이블 정의서에 의도를 남기기

테이블의 목적과 한 행의 단위, 각 열의 업무 의미, 자료형, 필수 여부, 기본값, 키와 인덱스, 참조·삭제 정책을 기록한다. 예를 들어 실습의 `shop_order_items.unit_price_at_order`는 주문 시점에 확정한 단가이며, 상품의 현재 가격이 바뀌어도 보존한다. 정의서의 규칙이 실제 스키마와 일치하도록 DDL과 함께 검토한다. [물리 모델링 실습과 테이블 정의서](11_physical_modeling_workshop.md)
