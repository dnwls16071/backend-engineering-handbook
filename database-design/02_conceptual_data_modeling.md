# Conceptual Data Modeling

개념 모델은 업무 담당자와 개발자가 같은 대상으로 이야기하는지 확인하기 위한 모델이다. 기록할 대상, 대상의 속성, 대상 간 관계를 정하고 각각의 이름과 의미를 합의한다.

## 1. 요구사항에서 엔티티 후보 찾기

“회원이 상품을 주문하며, 주문마다 구매 수량과 주문 시 단가를 남긴다”는 요구사항을 보자. 회원과 상품은 관리 대상이다. 주문은 행위의 결과로 남기는 기록이며, 수량과 주문 시 단가는 주문에 담긴 개별 상품의 속성이다. 명사와 동사는 후보를 찾는 단서다. 대상을 독립적으로 구별할 필요와 데이터의 생성·변경 시점을 확인한 뒤 엔티티와 속성을 정한다. [IBM Data Modeling](https://www.ibm.com/think/topics/data-modeling) · [Oracle Data Modeler Concepts](https://docs.oracle.com/en/database/oracle/sql-developer-data-modeler/22.2/dmdug/data-modeler-concepts-usage.html)

엔티티는 공통으로 기록할 대상의 유형이며, 인스턴스는 그 유형에 해당하는 개별 대상이다. `상품`은 엔티티, 상품코드 `P-100`인 병따개는 인스턴스다. 상품명과 가격은 속성이고, 상품코드가 각 상품을 유일하게 구분하는 규칙이 있다면 식별자 후보다. 여러 속성을 조합해 식별할 수도 있다. 구체적인 기본 키는 [논리 모델의 키](04_relational_keys.md)에서 다룬다.

## 2. 엔티티는 관점에 따라 분류한다

| 관점 | 분류 예시 | 판단에 쓰는 질문 |
| --- | --- | --- |
| 나타내는 대상 | 유형, 개념, 사건 | 실물인 상품, 분류 체계인 상품군, 발생 기록인 주문 중 어느 성격인가? |
| 업무 흐름 | 기본, 중심, 행위 | 회원처럼 먼저 등록되는가, 주문처럼 업무의 중심인가, 주문 항목처럼 상세 내역을 남기는가? |
| 존재와 식별 | 독립, 종속 | 주문 항목처럼 부모가 있어야 의미가 있는가? 항목 번호가 주문 안에서만 고유해 주문 식별자와 함께 써야 하는가? |
| 역할 | 연관 엔티티, 슈퍼타입과 서브타입 | 두 대상의 연결 자체에 속성이 있는가? 공통 속성과 하위 유형 고유 속성을 분리할 필요가 있는가? |

하나의 엔티티가 여러 관점에 해당할 수 있다. 주문은 사건이자 업무의 중심이다. 부모가 있어야 업무상 존재할 수 있는 규칙과 부모 식별자가 자식 식별자의 일부가 되는 규칙은 따로 확인한다. [IBM ERD의 엔티티 유형](https://www.ibm.com/think/topics/entity-relationship-diagram) · [Oracle Data Modeler의 식별 관계](https://docs.oracle.com/en/database/oracle/sql-developer-data-modeler/22.2/dmdug/data-modeler-concepts-usage.html)

## 3. 관계 양쪽의 최소·최대 수 정하기

카디널리티는 상대 엔티티와 맺을 수 있는 수 범위를 표현한다. 이 과정에서는 최대 수로 `1:1`, `1:N`, `M:N`을 구분하고, 최소 수로 필수 참여와 선택 참여를 구분한다.

| 질문 | 최소..최대 |
| --- | --- |
| 회원 한 명의 주문은 몇 건일 수 있는가? | `0..N` |
| 주문 한 건을 한 회원에 귀속하는 정책이라면 주문의 회원은 몇 명인가? | `1..1` |

까마귀발 표기에서는 관계 양끝의 원, 세로선, 까마귀발을 조합해 최소와 최대를 나타낸다. 주문과 상품의 다대다 관계에 수량이나 주문 시 단가가 필요하면 `주문 항목`을 연관 엔티티로 둔다. 항목 하나는 주문 하나와 상품 하나에 연결되며, 주문과 항목, 상품과 항목의 두 관계로 나뉜다. 같은 상품을 한 주문에서 별도 항목으로 여러 번 기록할 수 있는지는 요구사항에서 결정한다. [IBM ERD의 참여도와 카디널리티](https://www.ibm.com/think/topics/entity-relationship-diagram)

## 4. 용어 사전을 ERD와 함께 관리하기

용어 사전에는 업무 이름, 영문 이름, 정의와 적용 예시를 기록한다. 예를 들어 `단가`는 주문 항목에 적용된 한 단위의 가격으로, `판매가`는 현재 상품에 표시하는 가격으로 정의한다. 같은 단어가 쓰인 주문 화면과 통계에서 의미가 달라지는지 검토하고, 합의가 바뀌면 사전과 모델을 함께 갱신한다. [개념 모델링 실습](03_conceptual_modeling_workshop.md)
